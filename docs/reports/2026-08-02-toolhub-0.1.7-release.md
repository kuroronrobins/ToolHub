# ToolHub 0.1.7 配布・更新修正レポート

作成日: 2026-08-02

## Summary

- 既存 ToolHub 0.1.6 が次回起動時に検知できる完全インストーラー更新として、ToolHub 0.1.7 の公開候補を作成した。
- AgendaSnap v3 の自己完結型 Windows 配布物と、利用期限を撤廃した PDF Workbench 0.2.5 を App Pack として収録した。
- GitHub Release に有効な全 App Pack を含め、公開前後に SHA-256 を検証できるよう配布スクリプトを修正した。
- GitHub Release の公開、0.1.6 からの更新案内、更新適用後の公開経路確認は、ユーザー承認と GitHub 再ログイン後に実施する。

- Version: `0.1.7`
- Tag: `v0.1.7`
- Installer: `ToolHub_Setup_0.1.7.exe`

- Installer size: `442203484` bytes
- Target folder: `release/github_release_targets/v0.1.7`
- Update strategy: ToolHub 本体を 0.1.7 へ上げる完全インストーラー更新

0.1.6 の更新判定は ToolHub 本体バージョンを基準にしており、アプリ差分だけでは更新案内が出ない。そのため今回は、既存利用者へ確実に案内するため完全インストーラー更新を採用した。

## What Changed

- 有効な App Pack を GitHub Release のアップロード対象へ自動追加し、`app_manifest.json` と実ファイルの SHA-256 が一致しない場合は公開準備を停止するようにした。
- 公開候補フォルダ検証と公開 URL 検証が、installer と manifest だけでなく有効な全 App Pack を必須 asset として確認するようにした。
- AgendaSnap の `self-contained:windows-x64` runtime 契約を release verification が正しく扱えるようにした。
- PDF Workbench の ToolHub 表示を 0.2.5、利用期限なしの内容へ更新した。
- 0.1.7 の利用者向け更新案内に AgendaSnap v3 と期限なし PDF Workbench を明記した。

## Pre-Implementation Self Review

- 確認した観点: 0.1.6 の更新判定、GitHub Release の公開 asset、App Pack と manifest の整合性、runner/runtime 契約、実アプリ起動。
- 追加で確認したファイル: `docs/00_AI_CONTEXT.md`、`docs/05_build_and_release.md`、`docs/06_acceptance_checklist.md`、更新判定と release script の関連ファイル。
- 見落とし防止のために確認したこと: 公開 GitHub には v0.1.6 までしかなく、v0.1.7 の release/tag が存在しないことを読み取り専用 API で確認した。

## Post-Implementation Self Review

- 依頼範囲外の変更: なし。開始時点の未コミット変更は restore、削除、stage、commit していない。
- 既存仕様への影響: 既存 `app.yaml` と shared-env 契約を維持した。公開スクリプトは enabled App Pack を追加で要求するため、不完全な GitHub Release を防止する方向の厳格化となる。
- docs 更新要否: 本レポートへ戦略、成果物、検証結果、未確認項目を記録した。
- 未確認リスク: インストーラーは Authenticode 未署名。公開済み 0.1.6 からの実更新は公開後でなければ確認できない。
- Git 整合性リスク: 現在の公開候補は未コミット作業ツリーから作られており、既定の tag 対象は現在の HEAD `9c142238b045c44954654ac6def82a362b5c36c3` になる。artifact と tag のソースを一致させるには、公開前に対象を限定した release commit が必要。

## Publication Gate

公開前に次の承認・操作が必要。

1. ユーザー自身による `gh auth login -h github.com` の完了。
2. release 対象だけを選んだ commit を作成し、その commit に `v0.1.7` を付けることの承認。
3. Release title、notes、10 assets の最終承認。

公開後は public `manifest.json`、全 asset、SHA-256、0.1.6 の更新案内、更新適用、両アプリ起動を実機で再確認する。
